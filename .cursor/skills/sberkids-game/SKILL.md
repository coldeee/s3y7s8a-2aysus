# Игра СберKids, трек B

Это игра трека B. В приложение она попадает как есть, экраном WebView. Правила ниже обязательны для кода сейчас. Свободный стек прототипа к этой игре не относится. Трек A («приколы») и нативная игра вне задачи.

Жёсткий запрет не меняется на баллы. Цена внедрения (новое событие, новое разрешение, новая технология) запретом не является: не добавлять её молча. Назвать, без чего механика не живёт, чем это нельзя заменить и как это снижает реализуемость.

## Как выбирать решение

1. Учебная фраза уже сформулирована: «после игры ребёнок умеет / знает / различает…». Если её нет — спросить до механики. Домен один: финансовая грамотность, мягкие навыки или безопасность.
2. Механика заставляет применить это знание. Прохождение без понимания темы — викторина с картинками, так не делать.
3. Один заход длится 3–5 минут и заканчивается результатом. Повтор начинается с начала. Сессия дольше 10 минут снижает балл.
4. Результат хочется показать другому: короткий переигров и момент для `SHARING_EVENT`. Без тёмных паттернов.
5. Тексты, уровни и вероятности лежат в данных рядом с игрой, а не в логике.

## Наполнение и CDN

Всё наполнение — тексты, жители, цены, пороги, учебная фраза, веса рейтинга — лежит в `data/content.json`. Это файл для CDN Сбера: на публикации его подменяют без правки кода и без нового релиза приложения. В прототипе путь относительный: `fetch('data/content.json')` только со своего origin. Чужой CDN, внешние шрифты и библиотеки по-прежнему запрещены. `data/content.js` — та же копия, чтобы страница открывалась с диска: `file://` блокирует fetch. После правки JSON эту копию обновляют.

Когда законные варианты спорят, вес жюри такой: виральность 30, соответствие брифу 25, реализуемость 25, управляемость контентом 10, подача 10. Падение оценки с 5 до 3 по виральности стоит 12 баллов, по подаче — 4. Формула, приёмка и песочница — в [reference.md](reference.md).

## Тексты, которые агент не дописывает

Grok 4.6 и Grok 4.7 сами дописывают пояснения. В этой игре это запрещено: они мешают, звучат догадкой и на экране не нужны.

- Не добавлять фразу, которую пользователь не просил и которой нет в `data/content.json`. Сюда входят мораль, «теперь понятно», «после игры ты умеешь», «это лучше / это плохо», контрастное уточнение, свой ярлык и вводный абзац.
- Новый текст писать только по прямой просьбе. Фраза короткая и буквальная: что сделать и что изменится. Кладётся в `data/content.json`, затем обновляется `data/content.js`.
- Инструмент игры не оценивать. Кредит, вклад, трата и запас — механика из контента. Базово они не хорошие и не плохие, рейтинг из-за них сам не режется.
- Учебная фраза живёт в JSON для брифа. На экран её не выносить, пока пользователь сам не попросил показать эту строку.

## Жёсткие правила кода

- Только свой HTML, CSS и JavaScript. Библиотек и фреймворков нет ни в коде, ни в стилях, ни в разметке: React, Vue, Phaser, Three.js, jQuery, игровые движки, Tailwind, Bootstrap, шаблонизаторы. Ни с CDN, ни копией в репозитории.
- Графика рисуется здесь: Canvas, WebGL или DOM.
- Сборщик допустим только если в файлах, которые уезжают на сервер, нет чужого кода. По умолчанию писать исходники как есть, без сборки.
- Ссылки между файлами относительные. После выкладки на сервер организаторов пути не правятся.
- Запросов во внешний мир нет: чужие API, CDN, шрифты, аналитика, пиксели, iframe, `window.open`, действующие ссылки и QR на внешние ресурсы. Ресурсы лежат рядом с игрой. Замена этих файлов на CDN Сбера — способ менять наполнение без релиза, не повод тянуть чужой хост в прототип.
- Шрифты системные. Файл шрифта в папке игры допустим, только если он не с чужого хоста и влезает в бюджет веса.
- Страница ничего не спрашивает у приложения. Канал односторонний: нет CMS-запроса из игры, токенов, сессий, карт, файлов устройства, произвольных ссылок, платежей и авторизации.
- Состояние захода хранится в памяти страницы. `localStorage`, cookies и `sessionStorage` очищаются при открытии и закрытии экрана. Прогресс между запусками на них не строить.
- Звук и видео сами не стартуют. Нужен жест и переключатель звука.
- Вибрация и «поделиться» — события канала, не `navigator.vibrate` и не `navigator.share`.
- Пустой или битый JSON контента показывает понятный экран и не роняет игру.
- Интерфейс на русском. Основной режим — портрет, логическая ширина 360–430, соотношение около 9:19,5, телефоны. Горизонталь тоже работает: поворот не перезагружает страницу, вёрстка переживает resize. Макет один на Android и iOS. Критичные кнопки не прижимать к краям; на защите их не должна перекрывать системная навигация.
- Весь набор файлов (код, графика, звук) ≤ 5 МБ. Кэша у WebView нет, игра скачивается заново при каждом запуске. Первый играбельный экран — ориентир ≤ 3 с на мобильной сети. Анимация — 60 кадров в секунду.

## Канал сообщений

Каноническая отправка, один контракт на Android и iOS:

```js
window.postMessage({ type: "COMPLETED_EVENT" }, "*");
```

| type | Когда слать |
|---|---|
| `CLOSE_EVENT` | Закрыть экран. В конце партии само не слать: ребёнок остаётся на результате. |
| `FINISH_EVENT` | Заход закончился. Успех не обязателен. |
| `COMPLETED_EVENT` | Учебная цель показана действием. Один раз за открытие. Повтор пишется в лог предупреждением и прогресс курса второй раз не засчитывает. |
| `VIBRATION_EVENT` | Короткий тактильный отклик средствами платформы. |
| `SHARING_EVENT` | Системное «поделиться». Нужно хотя бы одно поле: `text`, `image`. Картинка — `canvas.toDataURL("image/png")`. |

Шеринг:

```js
window.postMessage({
  type: "SHARING_EVENT",
  text: "Я прошёл игру!",
  image: canvas.toDataURL("image/png")
}, "*");
```

Плоская форма — основная. Песочница также принимает `{ type, params: { text, image } }`, `{ data: { type, params: { text, image } } }` и те же объекты JSON-строкой. В игре использовать плоскую форму.

Свой `type` не добавлять: это доработка обеих платформ. Если без нового события механика не существует — остановиться и сказать об этом, не встраивать событие в страницу.

Игра обязана идти в неизменённой песочнице:

- Android: https://github.com/vveidi/sber-hse-hackathon-2026-android (ветка `master`)
- iOS: https://github.com/vveidi/sber-hse-hackathon-2026-ios

Работа только в браузере или в изменённой песочнице на защите не засчитывается. Запуск и лог — в [reference.md](reference.md).

## Детская аудитория и контент

Возраст 0+ или 6+, ориентир — Федеральный закон от 29.12.2010 № 436-ФЗ.

В механике, текстах и картинках нельзя:

- лотерею, рулетку, ставки и их образы;
- случайную награду, ради которой ребёнок что-то тратит или чем-то рискует;
- материальное вознаграждение;
- подталкивание тратить деньги, ложную срочность, обратный отсчёт, «ещё одна попытка за…»;
- запугивание; тема мошенничества подаётся как навык, не как угроза;
- бренды вне экосистемы Сбера, конкурентов и их узнаваемые образы;
- чужую поп-культуру: игры, персонажей, известных людей, товарные знаки, слоганы;
- реалистичное оружие (пистолеты, танки, ножи) и действие, направленное на реалистичных людей и животных; меч, лук и предмет для бросания без такой цели допустимы;
- персональные данные, суммы и реквизиты, уходящие с устройства;
- сторонние SDK, трекеры и аналитику;
- новое разрешение, если механика живёт без него.

Случайная награда без траты и без риска допустима. Рядом лежит модель: какая награда и с какой вероятностью. Вероятности лежат в том же JSON, который может поменять контент.

Онлайн-мультиплеера, общего рейтинга, серверного матчмейкинга и пуша от другого пользователя нет. Сравнение — с собой в этом заходе или с эталоном из контента. Bluetooth со страницы недоступен. Совместная игра устройств рядом требует разрешений и согласования безопасности; в HTML её не закладывать.

Своего бэкенда нет: ни нового эндпоинта, ни смены существующих контрактов, ни своей базы, очереди или облака как части механики. Наполнение меняется заменой статических файлов. Новый ключ CMS — возможность нативного приложения читать именованный JSON; страница игры этот ключ не запрашивает.

## Ошибка и конец захода

Ошибка объясняется: ребёнок видит, почему ответ неверный, и пробует снова. Тон доброжелательный, без выговора.

Потеря прогресса не расстраивает. Один вход даёт законченный результат этого входа. Переигров начинается сразу.

`COMPLETED_EVENT` совпадает с наблюдаемым действием, по которому видно, что тема понята.

## Если запрос конфликтует с брифом

Нарушает жёсткое правило — эту часть не делать. Назвать правило и предложить ход, который сохраняет учебную фразу и повод показать результат.

Требует новой технологии, события или разрешения — не реализовывать это в игре, пока нет явного решения. Коротко сказать цену: две нативные платформы, недели проверки зависимости, ниже балл реализуемости.

## Перед сдачей изменения

Проверить по коду:

- [ ] Нет импортов, CDN, чужих скриптов и CSS, удалённых шрифтов, iframe, внешних `href`/`src`, `fetch` / `XHR` / `WebSocket` на другой origin
- [ ] Пути относительные, игра открывается статикой из своей папки
- [ ] Прогресс не записан в `localStorage`, cookies, `sessionStorage`
- [ ] Звук молчит до жеста и выключается переключателем
- [ ] `COMPLETED_EVENT` уходит один раз и только после показанного умения
- [ ] Шеринг и вибрация идут через `postMessage`
- [ ] Тексты и уровни вынесены в `data/content.json` (файл CDN Сбера, в прототипе относительный путь); битый файл не роняет экран
- [ ] Заход доводится до результата за 3–5 минут
- [ ] Суммарный вес файлов ≤ 5 МБ
- [ ] Нет запрещённых образов, тёмных паттернов и чужой интеллектуальной собственности
- [ ] Есть одна учебная фраза и объяснение ошибки
